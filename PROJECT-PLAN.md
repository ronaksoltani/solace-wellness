# Project plan: solace

## Brief

**Type:** Website design

**Problem:** Wellbeing products can feel demanding when visitors simply need a gentle first step.

**Audience:** A visitor exploring short, low-pressure pause practices.

## Experience flow

1. Arrive at a direct, descriptive introduction.
2. Review the sample interface and its scope before interacting.
3. Try the core control: Try a local mood check-in and gentle demo practice.
4. See a local result or demonstration state without sending a request to a service.

## Interaction

A mood check-in is stored locally; practice buttons show a demo state.

## Key design decision

Keep language calm, choices small and interactions free of streak pressure.

## Boundaries

Fictional concept; practices are general interface samples, not clinical advice or care.

All named businesses, people, products, schedules, prices and quantitative values are fictional portfolio content. Replace them only with verified, permissioned material.

## Next iteration

Review all copy with qualified advisors and add a clear accessibility preference model.

## Learning goals

- Structure a complete page with meaningful headings, landmarks and labelled controls.
- Separate visual rules in CSS from interaction logic in JavaScript.
- Make states understandable with keyboard controls and live status text.
- Document assumptions and the boundary between a helpful prototype and a production service.
